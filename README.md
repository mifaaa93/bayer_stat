# TGAds Analytics Bot

Статистика читается **напрямую из MySQL**: `creos`,
`buyer_stats_today_start_sub`, `traffers`. В локальной SQLite **нет**
рекламной статистики: только привязки групп к байерам, обнаруженные
топики и контекст последних сообщений (не дольше семи суток).

## Конфигурация

Установите `pip install -r requirements.txt` и заполните `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=
ADMIN_IDS=123456789
OPENAI_API_KEY=
OPENAI_BASE_URL=https://ru.cheapvibecode.ru/v1
OPENAI_MODEL=gpt-5.6-sol
OPENAI_REASONING_EFFORT=medium
DATABASE_PATH=data/bot.sqlite3
LOG_PATH=data/bot.log
LOG_LEVEL=INFO
MYSQL_HOST=
MYSQL_PORT=3306
MYSQL_USER=
MYSQL_PASSWORD=
MYSQL_DATABASE=
```

### Ubuntu: ffmpeg для голосовых

Голосовые сообщения обязательно конвертируются перед транскрибацией:

```bash
sudo apt update
sudo apt install -y ffmpeg
ffmpeg -version
which ffmpeg
```

В `.env`:

```dotenv
FFMPEG_BIN=ffmpeg
TRANSCRIPTION_MODEL=gpt-4o-transcribe
TRANSCRIPTION_QUEUE_SIZE=50
```

Используйте MySQL-пользователя с **только SELECT** на трёх нужных таблицах
и `information_schema.COLUMNS`. Для подключения с внешнего сервера
необходимо разрешить его адрес на стороне MySQL. Пароли не пересылайте боту.
Старую базу со снимками удаляем: исторические данные доступны только при
наличии соответствующих дат в MySQL.

Логи пишутся в stderr и в файл `LOG_PATH` (по умолчанию рядом с SQLite:
`data/bot.log`, ротация по 5 МБ × 5 файлов). Для более подробной отладки
поставьте `LOG_LEVEL=DEBUG`.

`OPENAI_REASONING_EFFORT` передаётся в API как `reasoning_effort`
(`minimal` / `low` / `medium` / `high`). Пустое значение — параметр не
отправляется.

Бот читает схему нужных таблиц через `information_schema` при первом запросе.
Предполагаемые поля: `creos` — `date`, `creo_name`, `budget`, `id_traf`;
`buyer_stats_today_start_sub` — `date`, `creo_name`, `count_start`,
`count_sub`, `count_reg`, `count_ftd`; `traffers` — `id`/`id_traf`, `name`.
Схема проверена 26 сентября 2026 года: `traffers(id,traffer_name)`,
`creos(date,id_traf,creo_name,budget,...)`,
`buyer_stats_today_start_sub(creo_name,date,count_start,count_sub,count_reg,count_ftd)`.
Даты в обеих таблицах — ISO-строки вида `2026-09-26T00:00:00.000Z`,
`budget` — текст. В `buyer_stats_today_start_sub` нет ID байера: строки
сопоставляются по дате и имени креатива, как в исходном дашборде.
Дневные данные считаются из MySQL по датам событий; часовой пояс бота
фиксированный UTC+2.

**Качество данных:** у байера `id_traf=5` на 25 и 26 сентября 2026 года
все `budget` пусты. Бот честно показывает расход и показатели стоимости
как «нет данных», а не как 0. События (старты, подписки, регистрации,
FTD) при этом доступны; масштабировать кампании по отсутствующему расходу
нельзя.

## Админка

Запустите `python bot.py`, откройте личный чат с ботом и нажмите `/start`.
Админка доступна **только в личном чате ID из `ADMIN_IDS`**. В меню две
обычные кнопки: **Добавить группу** и **Список групп**.

Добавление: Telegram-кнопка «Выбрать группу» отправляет боту `chat_id`,
название и (если есть) публичный username. Telegram **не предоставляет
приватную ссылку-приглашение** через request_chat; для закрытой группы бот
должен быть добавлен в неё. Затем админ выбирает байера из MySQL-таблицы
`traffers` и подтверждает. Если в группе включены темы, перед выбором
байера появится выбор **General — вся группа** или конкретного топика.
Bot API не позволяет получить список всех существующих топиков. Бот
запоминает темы, сообщения из которых он видел после добавления в группу;
если темы нет в списке, отправьте в неё сообщение и нажмите «Обновить»
либо укажите числовой ID топика вручную. Уже добавленную группу можно
открыть из списка, сменить байера или топик, либо удалить. Список
постраничный, по 10 групп.
Если топик существовал до добавления бота, Bot API сообщает его ID, но
не настоящее название: в админке он отображается как
«Топик #ID (название не получено)». В карточке можно нажать
«Подписать топик в боте» и указать название вручную; это не меняет
название самого топика в Telegram. При создании/переименовании топика
в присутствии бота его название запоминается автоматически.
При выборе байера в этом же сообщении отображается его текущий статус
«(работает)» или «(пауза)». Сообщение редактируется на шаге подтверждения;
после успешной привязки в нём появляется кнопка «Посмотреть все группы».

В группе бот отвечает на упоминания, ответы на его сообщения и отдельное
слово «кит» (регистр не важен; «китовий» не запускает ответ).
Бот сохраняет сообщения в SQLite для контекста, в том числе
сообщения без обращения к нему. При выборе конкретного топика сообщения
других топиков не записываются в контекст; при выборе General — вся группа.
Имена и ID обнаруженных топиков сохраняются отдельно для админки, без
содержимого сообщений других тем. Устаревшая таблица `chat_history`
удаляется миграцией: контекст хранится только в `group_messages`.
Хранятся до 5000 сообщений на группу за последние 7 дней; модели
передаются последние 30. Новые вопросы во время подготовки ответа
ставятся в очередь без сообщения «Подождите». После завершения текущего
ответа накопившиеся вопросы одного топика и одной привязки байера
объединяются в один следующий запрос и ответ с разделами по вопросам.
Вопросы, поступившие во время ответа на пачку, относятся к следующей пачке.
Большие пачки делятся по размеру, без потери оставшихся вопросов;
вопросы из разных топиков не объединяются.
Голосовые сообщения из выбранного топика автоматически попадают в отдельную
очередь транскрибации. Сейчас работают два voice-worker’а одновременно:
Telegram-файл
скачивается, обязательно конвертируется в mono 16 kHz WAV через ffmpeg,
отправляется в `gpt-4o-transcribe`, а результат передаётся в обычную очередь
вопросов. Голосовое в General принимается из любой темы; в группе с выбранным
топиком — только из этой темы или как ответ на сообщение бота.
Для получения всех сообщений отключите Privacy Mode в BotFather и
удалите/добавьте бота обратно в группу (или сделайте бота администратором).
Байер
определяется **исключительно привязкой текущей группы**; AI не может
выбрать другого байера. Чтобы очистить контекст личного чата админа,
отправьте `/reset`. При смене байера и удалении группы её история удаляется.

AI-инструменты читают MySQL только `SELECT`-запросами:

| Инструмент | Назначение |
|---|---|
| `get_overview` | Итоги байера и, при необходимости, разбивка по дням |
| `get_funnel` | Этапы воронки, конверсии и стоимость результатов |
| `get_creative` | Один креатив по точному имени или подстроке |
| `list_creatives` | Поиск, рейтинг и постраничный список креативов |
| `compare_periods` | Сопоставление двух периодов |
| `compare_creatives` | Сравнение двух креативов |
| `find_anomalies` | Резкие изменения метрик между периодами |
| `get_data_availability` | Доступность дат и заполненность расходов |
| `get_source_statistics` | Статистика по источникам `ТГ`, `фб` и другим источникам |
| `compare_sources` | Сравнение источников и новых/исчезнувших креативов между периодами |
| `get_statistics` | Универсальная детальная выборка |

Поиск креативов выполняется в параметризованном SQL. Расходы с пустым
`budget` не считаются нулевыми; в затронутых периодах стоимость
регистрации и FTD не рассчитывается. Модель получает только данные байера,
привязанного к текущей группе. Источник определяется через `creos.id_blog`
и `bloggers.traf_type`. События из `buyer_stats_today_start_sub` относятся
к источнику только если связка `дата + креатив` однозначно соответствует
одному источнику и одному байеру; неоднозначные события бот отдельно
помечает как нераспределённые и не дублирует между источниками.

В группах бот реагирует на обычное упоминание `@BotName вопрос`,
ответ на его сообщение или отдельное слово «кит». Команд для запросов
статистики нет.
Если включён Privacy Mode, обычные упоминания не доходят до бота:
отключите privacy через BotFather `/setprivacy` и удалите/добавьте бота
обратно в группу. Альтернатива — сделать бота администратором группы.

Бот работает пока запущен процесс `python bot.py`. Сборщика, фонового
обновления статистики и файлов Google Sheets в проекте больше нет.
Финальный ответ AI запрашивается без streaming: Telegram получает один
статус и затем одно финальное редактирование сообщения с разметкой.
